## 摘要
训练能够调用API的大语言模型（LLM）代理需要大量高质量的执行轨迹。然而，大规模收集此类数据通常需要完全实现的环境，包括可执行的API以及预填充的现实后端数据库，这成为可扩展性的主要瓶颈。为克服此问题，我们提出一种无环境合成数据生成方法，该方法利用LLM作为即时数字世界模型。仅给定API规范，我们的方法生成模拟代理与有状态环境之间交互的执行轨迹。具体而言，LLM首先生成由所提供API可解决的多样化任务。然后，一个教师代理迭代地解决每个任务，同时一个LLM模拟器根据任务上下文和模拟历史生成连贯的合成API响应。最后，LLM评判员过滤轨迹以确保生成数据集的质量。我们在具有挑战性的AppWorld和OfficeBench基准测试上评估了我们的方法，这些基准包括信息检索和状态更改任务。在我们的合成数据上微调模型带来了显著的性能提升，表明无需任何可执行环境即可生成对API调用代理有效的监督。我们的结果确立了基于LLM的API模拟作为训练跨不同API生态系统的代理的一种实用且可扩展的解决方案。

## Abstract
Training API-calling large language model (LLM) agents demands massive amounts of high-quality trajectories. However, collecting such data at scale typically requires fully implemented environments with executable APIs and realistic, pre-populated backend databases, creating a major bottleneck for scalability. To overcome this, we propose an environment-free synthetic data generation approach that leverages LLMs as on-the-fly digital world models. Given only API specifications, our method generates trajectories mimicking interactions between an agent and a stateful environment. Specifically, an LLM first generates diverse tasks solvable with the provided APIs. A teacher agent then iteratively solves each task while an LLM simulator generates coherent synthetic API responses conditioned on the task context and simulation history. Finally, an LLM judge filters the trajectories to ensure the quality of the resulting dataset. We evaluate our approach on the challenging AppWorld and OfficeBench benchmarks, which include both information-retrieval and state-changing tasks. Fine-tuning models on our synthetic data yields significant performance gains, demonstrating that effective supervision for API-calling agents can be generated without any executable environment. Our results establish LLM-based API simulation as a practical, scalable solution for training agents across diverse API ecosystems.

- **整体含义**：本文提出一种**无需任何可执行环境**的合成数据生成范式，仅需 API 规范（名称、输入输出 schema），利用 LLM 作为动态数字世界模型来模拟环境反馈，从而大规模生成高质量的代理轨迹。该范式将数据生成从“工程问题”简化为“轻量级规范问题”，可无缝扩展至任意 API 生态系统，为训练鲁棒的 API 调用代理提供了可扩展的解决方案。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：现代 LLM 在预训练中习得了丰富的世界知识，可以充当动态数字世界模型。给定 API 规范、输入参数、任务指令和历史交互，LLM 能合成逼真的执行结果，并准确反应底层状态变化。基于此，本文提出 **ESAT** (Environment-free Synthetic Agentic Trajectory generation) 流水线。
- **关键技术细节（三阶段）**：
    1. **任务合成**：
        - 采用**分桶生成**（bucketized generation）：按难度、动作类型、任务焦点、应用数量、每应用 API 数量等维度组合成 360 个配置桶，随机顺序处理。
        - **逆频率采样**：维护应用和 API 的使用计数，优先选择使用次数少的应用和 API，确保均匀覆盖。
        - LLM 生成候选任务后，由同一个 LLM 作为判断器筛选有效任务，再经**任务重写**（压缩过程性描述为自然意图），最后再次判断。
    2. **轨迹合成**：
        - **教师代理**（teacher agent）迭代调用 API 解决问题，同时一个 **LLM 模拟器**根据任务上下文、交互历史、用户信息等动态合成 API 响应。
        - 模拟器维持**按应用的历史记录**，确保状态一致（如之前创建的实体在后续调用中仍存在）。
        - 核心规则：数据一致性、数据多样性、数据真实性、schema 合规。
        - **质量控制**：输入参数程序化验证；输出 schema 校验和语义一致性判断（通过另一个 LLM）；失败时循环重试，最多固定次数。
        - 轨迹终止条件：代理调用完成 API、超步、使用未规划的应用、或模拟器失败。
    3. **轨迹过滤**：
        - 由 LLM 评判器（Gemini-3.1-Pro）对完成任务的轨迹进行多重评估，仅保留多数判决为正面的轨迹，确保训练数据质量。

- **流程概括**：API 规范 → 任务生成器 LLM（+判断器筛选）→ 教师代理 + 模拟器 LLM 交互 → 轨迹评判器 LLM 过滤 → 高质量数据集。

## 3. 实验设计：数据集、基准、对比方法

- **数据集/基准**：
    - **AppWorld**：多应用复杂任务基准，含 457 个 API（9 个日常应用），平均每个任务需 10 个 API、45 次调用。测试集分为 Test-Normal（168 任务）和 Test-Challenge（417 任务，含两个未见应用）。
    - **OfficeBench**：办公自动化基准，20 个 API（8 个应用），评估跨应用的长流程任务。淘汰 OCR 依赖和不可解任务后，有效任务为 26 个两应用和 46 个三应用任务。
- **训练数据来源**：
    - ESAT-AW7：用 AppWorld 中 7 个应用的 340 个 API 生成约 9K 轨迹（排除测试集中两个未见应用）。
    - ESAT-S52：用 52 个全新合成应用（1017 个 API，独立于 AppWorld）生成 6K 轨迹。
    - ESAT-OB：用 OfficeBench 的 20 个 API 生成 1.7K 轨迹。
    - AWT（AppWorld 真实环境采集数据）：基于 90 个训练任务，每个任务用 GLM-5.1-FP8 在真实环境中生成 8 条轨迹，筛选成功轨迹后得 634 条。
- **对比方法**：
    - **零样本**：多种 off-the-shelf 模型（Gemini-3.1-Pro, GLM-5.1-FP8, GPT-4o, Nemotron-3-120B）。
    - **现有合成数据集**：ToolAlpaca、ToolACE、Nemotron，以及 Simia（只对比 OfficeBench）。
    - **真实环境数据**：AWT。
- **训练模型**：Qwen3（1.7B/4B/8B/14B）和 Qwen3.5（2B/4B/9B/27B），共 8 种规模。

## 4. 资源与算力

## 6. 主要结论与发现

- **ESAT 数据极其有效**：在 AppWorld 上，微调 ESAT-S52-AW7 数据相比零样本提升最高达 50.5%（Qwen3-8B Test-N），整体提升 8.4%–50.5%。在 OfficeBench 上，最高提升 60.5%（Qwen3.5-2B 两应用）。
- **强泛化到新 API**：仅使用 52 个合成 API（与目标环境无关）生成的 ESAT-S52 数据，微调后即大幅超越零样本，甚至超过真实环境 AWT 数据在多数模型上的表现。
- **超越真实环境数据**：在 AppWorld 上，几乎所有模型使用 ESAT-S52-AW7 数据达到的性能均优于使用 AWT 数据；两个数据集结合可进一步提升（最多 15.3%）。
- **知识蒸馏效果**：小模型（4B–8B）经 ESAT 微调后，性能接近或超过大模型 GPT-4o 和 Nemotron-3-120B。
- **LLM 评判质量高**：Gemini-3.1-Pro 作为轨迹过滤器达到 95.2% 精确度（与真实环境标签对比），且与人类专家一致性达 95%，Kappa=0.90。
- **模拟器可靠**：93.7% 的模拟 API 响应经 GPT-5.1 评判有效；短响应失败率低（<500 token 失败率 2-3%），长响应失败率上升（>2000 token 失败率 23%）。
- **现有合成数据集局限性**：ToolAlpaca、ToolACE、Nemotron 在复杂状态环境上几乎无效，甚至可能降低性能。

## 7. 优点

- **方法创新性**：首次提出完全无环境、仅依赖 API 规范的轨迹合成流水线，将数据生成从基础设施密集型转变为轻量规范输入。
- **状态一致性**：模拟器通过分应用历史维护连贯的虚拟状态，支持支持状态变更（write）API，生成真实的多人多步轨迹。
- **覆盖均匀性**：通过分桶和逆频率采样确保任务多样性，API 覆盖率达 99%+（AppWorld），避免崩塌。
- **质量保证**：多层过滤（输入验证、schema 检查、语义裁判、轨迹裁判）确保数据高保真。
- **实验全面且结果显著**：覆盖多种模型规模、多数据集、多对比基线，并且有消融和人类评估支持。
- **实用性与可扩展性**：可快速迁移至任意新 API 生态系统，降低训练 API 代理的门槛。

## 8. 不足与局限

- **模拟器局限性**：长响应（>2000 token）失败率较高（23%），依赖 GLM-5.1-FP8 能力，可能无法在所有场景下保持一致性；使用更强模型或可缓解，但会增加成本。
- **任务分布不均**：多应用任务（2-app, 3-app）生成比例较低，尽管采用了逆频率采样，但 LLM 生成器自然偏向单应用任务；可能影响模型在多应用协调上的泛化能力。
- **教师代理依赖**：轨迹质量依赖于教师代理（GLM-5.1-FP8）的能力，若教师自身失败率高，则数据集规模受限（约 20-45% 的任务无法成功生成轨迹）。
- **评估基准局限**：AppWorld 和 OfficeBench 虽然挑战性强，但仍只覆盖有限数量的应用域；跨更广泛、更真实的 API 生态（如企业级 API，动态 Web API）的泛化性尚未验证。
- **计算成本**：数据合成阶段多次调用 LLM（生成、改写、评判、模拟、再评判），总 LLM 调用量较大，但相比搭建真实环境仍属轻量。论文未量化具体成本。
- **隐式假设**：假设 API 规范完全且准确，若规范不完整或有错误，合成数据可能偏离真实行为。未探讨规范噪声下的鲁棒性。
- **无真实用户数据验证**：合成数据模式完全由模拟器创造，与真实世界用户行为分布的偏差未知，可能引入系统性偏差。
